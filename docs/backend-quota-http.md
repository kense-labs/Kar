# Workbench quota reset

Owner-authenticated HTTP uses the selected project's native installation and credential home. Supply a private per-client `Kar-Auth-Client` header on actions. Under `/projects/{project}/accounts/{runtime}/quota/resets`, POST the collection to inspect. Codex reads account limits and named credits. Claude opens its supported native terminal menu with the existing spend guard. The fixed workbench's Claude grant reader disables its credential-file transport on macOS. Kar uses its native Claude CLI on macOS.

POST `/redeem` with `{"request_id":"<UUID>","reset_id":"<native ID>"}`. Claude accepts its native five_hour, weekly, fable and full entries. Set `five_hour_limit_consent` only for an explicitly authorized legacy five-hour spend. Reuse the UUID on timeout, process restart or disconnect. Concurrent aliases of the same credential home serialize. A different action cannot reuse the UUID. Kar reads fresh limits after a confirmed reset. A second HTTP call for a completed action returns the durable outcome.

A new action is held while a previous native request has an indeterminate outcome. Retry the same UUID on the original account. Codex uses its own idempotency key. Claude consults its pre-submit journal. If identity or the native outcome cannot be recovered, inspect the original credit history, then POST `/{request}/acknowledge` with `{"checked_native_history":true}` to record the unknown outcome and allow new work. Acknowledgement cannot spend.
