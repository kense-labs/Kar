# Kar model collaboration on macOS

A native chat lease discovers these tools through the normal MCP endpoint. The owner can grant environment writes using the chat's existing model-tool permissions endpoint with mode execute and environment_writes set to true. A paired device can manage its chat permissions but cannot grant environment writes. Plan mode narrows the lease's permissions. Environment-wide changes also require a current model turn.

| Operation | Entry and effect |
| --- | --- |
| Attachments | kar_attachment_prepare_upload issues a bounded ticket for the caller's project and chat. PUT the exact bytes at upload_url. kar_attachment_discard removes a pending upload prepared by that chat. kar_thread_send_attachments claims the bytes for the same chat and submits them to its durable queue. Reuse input_id to recover a lost receipt. Image and file delivery use the normal native chat input path. |
| Message during a turn | kar_send_to_user publishes the provided Markdown to that turn's journal while the provider is running. The chat feed and subsequent snapshot use the same journal. |
| Structured output | A normal message or queued input can include requested_output_schema. The saved schema follows that input ID across a restart. The native prompt includes the schema and instructions for kar_submit_output. Successful validation writes the submitted JSON to the active turn's structured_output. Validation uses jsonschema 0.63.1 (MIT, Rust 1.85 or newer) with default features disabled. The validator has no HTTP or filesystem schema resolver. |
| Preferences | kar_environment_read and GET /environment expose the stable host ID, platform, server version, label and preferences. KAR_ENVIRONMENT_LABEL can supply the name. kar_environment_preferences_update and the owner preferences endpoint update fields individually. Prompt suggestions share the existing settings store. The default worktree origin preference applies after explicit request and project overrides. Clients can read thread environment mode, provider update checks, background activity and source-control writing style from the same descriptor. |
| Theme | kar_theme_read and kar_theme_set list, publish and select built-in or custom palettes, light/dark variations, CSS and the active appearance. GET /environment/theme exposes the active preference to clients and takes an optional theme_id for the full published file. This backend check does not verify visual application by a desktop client. |
| Peer environments | kar_environment_link creates a chat-bound owner request. The owner selects the HTTPS origin (loopback HTTP is allowed for local testing) and supplies the target's ordinary single-use Kar pairing credential in the private response. The target issues a device session, whose credential stays on the host. kar_environment_links checks saved peers and kar_environment_read accepts an environment_id to read a linked Kar descriptor. kar_environment_unlink removes local access and attempts to revoke the remote device. It returns the remote confirmation state. The originating chat receives the link result through its original queue identity. |
| Feedback | kar_feedback records a Kar report. A user-requested report opens an owner card with the captured conversation excerpt, limited to the chosen recent turns. The owner can decline, approve just the report, or approve with the displayed conversation. KAR_FEEDBACK_URL selects the host-owned destination. Without a destination, an accepted report remains stored locally with sent set to false. The backend records an uncertain delivery after loss of a response. |
| Private input | kar_request_secret opens an owner-only card during the caller's run. It accepts a single input or separate named fields. A saved result returns a one-use secret_ref scoped to the project and chat, or owner-readable files when file delivery is selected. A supplied value must appear in the current user turn. Return data, card metadata and chat notifications exclude the entered values. Private files expire after 24 hours, checked at startup and periodically while Kar is running. A restart cancels a pending private interaction. |

Owner cards use GET /projects/{project}/chats/{chat}/collaboration/requests. POST a decision to the request ID below that route with accept and optional input. A link approval takes url and credential. A feedback approval takes include_conversation. A private-input approval takes a map with value for one field, or its requested names. The host can revoke a normal peer under /access/devices. A paired device can end its own session at DELETE /access/current-device.

The behavior comparison uses 2808e878de91aacc7fb82887f18414976be7ae34 under apps/server/src/mcp/toolkits. The attachment, environment, theme, feedback and message handlers define their respective operations. The orchestrator handlers define environment links and private requests. The thread handler and orchestration-v2/runOutput.ts define per-turn JSON validation.

## Reproduction

Compile with cargo check --locked --all-targets. Run cargo test --locked --test workbench_mcp for normal MCP and HTTP coverage. Its Rust protocol peer holds a live native-shaped turn to verify Markdown, output validation, a real private terminal-readable file and permission attenuation. The network case starts two local Kar processes and checks pairing, peer discovery and revocation. The fixture's feedback destination is disabled. These are offline cases compiled for consolidated execution. Remote TLS, delivery to a configured feedback collector, and supplier accounts need their own opt-in environment and were not exercised by this development check.
