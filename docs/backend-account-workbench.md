# Workbench account operations

Owner-authenticated requests select a project and one runtime. Two UI clients sharing the workbench owner login can generate different per-client keys. Use a randomly generated secret of 32–128 alphanumeric, hyphen or underscore characters in the `Kar-Auth-Client` header. Keep this secret in the initiating client. A flow with such a binding accepts polling, answers and cancellation only with the same key, even when another client knows its flow ID. Responses carrying login URLs, verification codes and prompts stay in the in-memory flow with a ten-minute deadline. The native login event distinguishes provider browser URLs and device codes. The vendor confirms the account result.

For built-in drivers use `/projects/{project}/accounts/{runtime}`. GET returns account status. GET `/methods` reports support for the hosted reader, login, logout and usage operations as applicable; GET `/quota` returns the native meter, a reauthentication request, an unavailable result or an unsupported capability. POST `/login` or `/logout` with the per-client header returns a flow ID. GET or DELETE `/flows/{flow}` with that header observes or cancels the flow. Cancellation releases the Kar runner. The supported native methods remain authoritative in `src/account/{login,logout}.rs` and `src/account/quota/mod.rs`. Hosted login includes Codex, Droid, Qoder, Grok, Kimi, CodeBuddy and Cursor. Quota readers include Codex, Claude, Grok, Antigravity, Droid and Kimi. A reported unsupported capability identifies the Kar adapter boundary; it does not establish what an independent vendor API can do.

For owner-managed ACP agents and named profiles use `/projects/{project}/acp-registry/{runtime}/auth`. GET `/methods` negotiates advertised methods. Login supports the advertised CLI, browser/URL elicitation, headless and credential prompts; the original process receives replies. Only an advertised logout method is invoked. DELETE `/credentials` removes stored per-runtime variables. Supply the same `Kar-Auth-Client` header at login/logout and throughout the flow. Legacy clients that start a dynamic flow without the header retain the original private flow-ID contract. ACP has no standard quota query.

`cargo test --locked --test workbench_acp_registry` exercises owner-only HTTP routes with disposable native peers, source-client denial and provider capability projection. The native account tests in `tests/account_live.rs`, `tests/account_quota_live.rs` and `tests/account_device_live.rs` define their opt-in provider and profile prerequisites. A live browser/device sign-in requires a tester-controlled account and explicit pairing. Native logout must use a disposable signed-in profile. Source compilation and protocol fixtures do not constitute live OAuth or billing results.

The fixed workbench account controller also supports same-credential binding coordination, account import/reconnect, provider-specific feedback and MCP-server sign-in. These separate actions are outside the native Kar account reader added here. The local built-in sign-out path does not drain every running chat sharing a vendor profile.
