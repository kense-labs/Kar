# Workbench MCP applications

The fixed workbench exposes application controls for Codex and Claude. Kar links each card to a completed tool item in the selected project's chat, turn, and original native root. Ordinary tool output cannot select a server. Open, requests and context use the existing authenticated workbench client.

* `POST /projects/{project}/chats/{chat}/turns/{turn}/mcp-apps/{item}/open` validates the native tool and reads its declared HTML resource from the original provider. A matching `ui://` resource, MIME type `text/html;profile=mcp-app` and a nonempty document of at most 5 MiB are required. Its response includes the application reference and current controller stream UUID.
* Append `/requests` to the item path. Send `{"action":"tool_info","stream":"…","name":"…"}` for the native tool schema, display title, visibility and read-only hint. Use `call_tool` with an arguments object and a stable `command_id`. Use `read_resource` with a URI. All three operations run on the originating server. A stopped or replaced controller rejects an old stream. Successful calls retain their exact receipts. An unacknowledged call tells the client to check the server before explicitly issuing another command.
* Append `/context` to the item path. Send `{"conversation":"<chat UUID>","content":[{"type":"text","text":"…"}],"structured_content":{"key":"value"}}`. A card can update its chat or a fork descendant in the same project. An empty update clears it. Text and serialized structured content together are limited to 16 KiB per card. The next admitted ordinary model turn snapshots all applicable context alongside its input. Context persists across restart and handoff. The user message stays independently identifiable in the timeline. An already running native model call retains the input it received.

Codex negotiates the UI MIME extension and identifies cards by `mcpAppUi.resourceUri`, `mcpAppResourceUri` or `appContext.resourceUri` on a native `mcpToolCall`. It uses thread-scoped `mcpServerStatus/list`, `mcpServer/tool/call` and `mcpServer/resource/read`. Claude must advertise `mcp_tool_ui_meta_v1`, `mcp_read_resource_v1` and `mcp_call_result_not_for_model_v1`. Its connected MCP tool inventory supplies the app resource URI. The adapter checks overlapping server names, normalized tool-name collisions, model-only visibility and the effective permission rules before calling `mcp_call` with result isolation. An unreadable or incomplete rule inventory prevents a call. Claude's MCP inventory omits input schemas, so its card reports the same generic object schema as the fixed workbench. Other adapters currently have no MCP card session implementation in the fixed workbench.
