# 访客提议的续投和附件留存

工作台行为基线为 `2808e878de91aacc7fb82887f18414976be7ae34`。固定源码的 `packages/contracts/src/guestShare.ts` 定义配额，`apps/server/src/orchestration-v2/GuestShareDecider.ts` 的 `trimResolved` 和 `releasedGuestAttachmentIds` 定义裁剪及附件释放，`apps/server/src/guest/GuestShareService.ts` 的 `attachment` 和 `GuestShareService.test.ts` 的跨聊天用例定义读取范围。`guestAttachments.ts` 定义非空文件和声明为图像时的文件头检查。

| 操作 | Kar 的预期结果 |
| --- | --- |
| 在同一分享提交草稿 | 每条最多 4 个附件、合计 10 MiB，以解码字节计。待处理提议最多 3 条、附件合计 20 MiB。相同访客使用相同请求 UUID 和内容重试时返回同一提议，即使配额已满。 |
| 主人驳回、替换、撤销或等候分享过期 | 释放尚未获准发送的附件内容。访客凭据到期或撤销时停止访问及订阅。保留最新提交的 20 条已决提议、全部待决提议。更早的已决提议仅保留重试所需的摘要、ID 和决定。 |
| 主人接纳后断开 HTTP 或重启 | 使用同一提议 UUID 和原聊天的 ChatStore 队列。发送前恢复工作区附件，队列收据已存在时直接对账。收到原生重复回执也完成接纳；原生拒绝、撤回、取消和过大都有各自的投递状态。 |
| 已有发送尝试、缺原生回执 | 返回 `status=sending, delivery=uncertain`，继续用同一 UUID 对账。恢复后续有确定未发送记录的排队输入。 |
| 读取已发送附件 | 原聊天和仍可见的原回合授予读取权，已决提议被裁剪后仍能读取。重新分享原聊天可读取同一份内容；其他聊天凭据、过期凭据和已驳回文件均拒绝访问。工作区副本被修改后访客获得的仍是原件。 |
| 配对设备访问聊天、项目、终端及预览 | 区分未配对、已授权和已撤销凭据。设备配对票据只能兑换一次。服务重启保留配对与撤销结果。 |

本批在 Apple Silicon macOS 的 Rust `aarch64-apple-darwin` 上执行 `cargo check --locked --all-targets` 和 `git diff --check`。下列统一验收用例已编入正常 CLI/HTTP 集成目标，等待执行。

```sh
cargo test --locked --test workbench_remote_access
```

测试使用 `kar workbench`、本机回环 HTTP、两个独立客户端、私有聊天状态和落盘的 stdio 协议对端日志。恢复场景包含工作区暂时不可写导致接纳后尚未入队、聊天投递已有凭据但私有附件尚不能归档、对端已收到请求却没有回执或可恢复原生历史、以及后一条仍在 FIFO 等待。各断点重启工作台后通过正常 HTTP 查询状态，并核对派发次数、提议 UUID、回合 UUID。附件留存场景覆盖上限、连续 21 次驳回、重放前后 ID、附件读取和分享过期。上述断点的文件系统故障由测试在临时目录制造。迁移用例另用旧版注册表结构和普通消息入口已写下的实际回合日志，验证内联附件与尚未结案的旧版投递。

真实跨设备待验需要另一台授权设备和可到达的工作台连接。使用同一组项目、终端、预览、提议和附件入口，在撤销后核对新请求及原订阅。真实模型待验需要对应版本的供应商程序、可用凭据及原生记录；按相同断点对照供应商输入 UUID、Kar 回合与实际模型调用次数。固定工作台的一次性访客邀请与 Kar 现有的同一邀请可创建独立访客凭据有一项差异，本批保留 Kar 原有的多访客产品行为。
